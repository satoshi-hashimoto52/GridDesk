# ワークスペース仕様

## ワークスペースとは

ワークスペースは、GridDesk のユーザーデータを保存するフォルダです。アプリ本体とは分離され、登録したアイコン、ジャンル、セル状態、設定、バックアップをワークスペース内にまとめます。

## Obsidian Vault 的な考え方

GridDesk は Obsidian の Vault のように、フォルダ単位で環境を管理します。アプリを更新してもワークスペースは残り、ワークスペースをコピーすれば別 PC でも同じ登録情報を開けることを目指します。

## フォルダ構成

```text
MyLauncherVault/
├─ launcher.db
├─ settings.json
├─ path_aliases.json
├─ icons/
├─ backups/
└─ exports/
```

## 各ファイル/フォルダの役割

| パス | 役割 | 現在の実装状況 |
| --- | --- | --- |
| `launcher.db` | ジャンル、アイコン、削除済みセルなどを保存 | 実装済み |
| `settings.json` | UI 設定、バックアップ設定など | 生成と読み込みは実装済み。一部 UI 反映は未実装 |
| `path_aliases.json` | PC ごとの差分を吸収する alias 定義 | 生成と起動時の一部解決は実装済み。編集 UI は未実装 |
| `icons/` | カスタムアイコン保存先 | フォルダ作成のみ実装済み |
| `backups/` | DB/設定のバックアップ保存先 | 実装済み |
| `exports/` | エクスポートデータ保存先 | フォルダ作成のみ実装済み |

## PC 移行時の流れ

1. 旧 PC のワークスペースフォルダをコピーします。
2. 新 PC に配置します。
3. GridDesk でそのフォルダを開きます。
4. 絶対パスが変わった場合はパス修正が必要です。

パス一括置換や alias 編集 UI は今後実装予定です。

## パスの考え方

| 種類 | 例 | 現在の扱い |
| --- | --- | --- |
| 絶対パス | `/Users/example/Documents/a.pdf` | 登録/起動に対応 |
| 相対パス | `docs/a.pdf` | ワークスペース基準で起動時に解決 |
| エイリアスパス | `{Documents}/a.pdf` | `path_aliases.json` を使った起動時解決に一部対応 |
| URL | `https://example.com` | 登録/起動に対応 |

## バックアップ方針

現在の実装では、次のタイミングでバックアップを作成します。

| タイミング | 実装状況 |
| --- | --- |
| ワークスペース起動時 | 実装済み |
| DB 更新前 | 実装済み |
| 手動バックアップ | 実装済み |
| アプリ終了時 | 今後実装予定 |

保存世代数は `settings.json` の `backup.maxGenerations` を参照し、既定値は 30 件です。

## OneDrive / Dropbox / NAS に置く場合の注意点

SQLite DB は同時書き込みに注意が必要です。同期フォルダや NAS に置く場合は、次の運用を推奨します。

- 複数 PC で同時に同じワークスペースを開かない
- 同期が完了してから別 PC で開く
- `backups/` を定期的に確認する
- 破損時はバックアップから復旧する

同期競合を検知する仕組みは今後実装予定です。
